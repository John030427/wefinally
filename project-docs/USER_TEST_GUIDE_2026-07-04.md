### 2.3 微信开发者工具

1. 导入目录：`D:\wefinal\WeFinally婚恋小程序项目\WeFinally婚恋小程序项目\miniprogram`
2. 勾选“不校验合法域名”
3. 模拟器调试默认使用 `miniprogram/app.js`：

```js
DEFAULT_API_BASE_URL = 'http://127.0.0.1:3000'
```

4. 真机调试不能用 `127.0.0.1`，手机会把它理解为“手机自己”。真机必须改为电脑局域网 IP，例如：

```js
getApp().setApiBaseUrl('http://192.168.1.23:3000')
```

在微信开发者工具 Console 执行上面这句，`192.168.1.23` 换成你电脑当前 IPv4；不要原样输入“你的电脑IPv4”。执行后看到 `{ ok: true, apiBaseUrl: ... }` 才算成功；如果弹出“API 地址无效”，说明地址仍是占位符或格式不对。

5. 清缓存：开发者工具顶部菜单“工具” → “清除缓存” → “全部清除”，然后点“编译”。真机预览仍异常时，微信里删除该小程序最近使用记录后重新扫码。

6. 重新编译后先看 Console：

```js
getApp().globalData.API_BASE_URL
```

如果显示 `http://127.0.0.1:3000`，说明真机地址还没切过去。

### 2.3.1 清空本地状态，模拟初始注册

清空微信开发者工具缓存可以模拟“第一次打开小程序”的前端状态，但它只清理本地 Storage / 会话缓存，不会删除后端数据库里的用户。

适合模拟：

- 首次打开小程序
- 未登录状态
- 重新走登录页、协议页、注册页
- 重新测试本地 Storage、token、API 地址切换

不能单独模拟：

- 同一个 `openid` 在后端变回新用户
- 已注册用户重新触发 `needRegister`
- 后端匹配记录、VIP、见面安全记录清空

完整恢复“新用户注册状态”有两种方式：

方式 A：换一个测试 openid，最推荐。

```env
DEV_WX_OPENID=uat_register_20260706_001
```

然后重启后端，开发者工具执行：

1. 顶部菜单“工具”
2. “清除缓存”
3. “全部清除”
4. 点击“编译”
5. 重新点击“微信一键登录”

开发者工具 Console 也可以直接切换本次调试 openid，不需要反复改 `.env`：

```js
getApp().resetLocalForRegistration('uat_register_20260706_002')
```

然后重新点击“微信一键登录”。这会清掉本地 token、协议状态和择偶配置冷却缓存，并让下一次 dev 登录使用新的 openid。注意：这只在本地开发登录模式下生效。

已登录到旧用户首页时，也可以直接点首页底部测试按钮：

```text
开发测试：重新注册用户
```

它会自动生成一个新的 `uat_register_时间戳` openid，清空本地登录态并回到登录页。真机仍显示老 ID 时，先点这个按钮；如果按钮不存在，说明手机预览包还是旧代码，需要重新编译并重新扫码。

方式 B：清后端数据库里的当前测试用户，适合复用同一个 openid。执行前先确认不是正式数据。

```sql
DELETE FROM user_match_log
WHERE user_id IN (SELECT id FROM `user` WHERE openid = 'uat_register_001')
   OR match_user_id IN (SELECT id FROM `user` WHERE openid = 'uat_register_001');

DELETE FROM user_match_setting
WHERE user_id IN (SELECT id FROM `user` WHERE openid = 'uat_register_001');

DELETE FROM meet_report
WHERE user_id IN (SELECT id FROM `user` WHERE openid = 'uat_register_001');

DELETE FROM `user`
WHERE openid = 'uat_register_001';
```

判断是否恢复成功：

- 登录后进入协议页，而不是直接进入首页
- 后端 `/api/auth/wx-login` 返回 `needRegister=true`
- Storage 里没有旧 `wf_token`

注意：开发者工具模拟器不是完整真机。它能模拟注册流程和多数页面交互，但不能完全代表手机网络、定位授权、拨号、支付、包体限制、微信合法域名校验。

### 2.3.2 真机网络失败排查

1. 电脑执行 `ipconfig`，找 Wi-Fi/以太网的 IPv4，例如 `192.168.1.23`。
   - 一般选真实网卡：`无线局域网适配器 WLAN` 或 `以太网`。
   - 不要优先选 `vEthernet`、`Default Switch`、`WSL`、`Tailscale`，除非你确定手机也能访问这个网络。
2. 后端保持 `npm run dev` 运行。
3. 手机和电脑连同一个路由器，不要一个用热点一个用公司内网。
4. 开发者工具勾选“不校验合法域名、web-view、TLS 版本以及 HTTPS 证书”。
5. Console 执行，注意把 IP 换成第一步查到的真实 IPv4：

```js
getApp().setApiBaseUrl('http://192.168.1.23:3000')
```

6. 真机重新扫码预览。
7. 如果还失败，在电脑浏览器打开 `http://192.168.1.23:3000/api/common/health`（IP 同样替换成你的真实 IPv4），能打开才说明手机也有机会访问；打不开就是防火墙/网络隔离问题。

如果手机和电脑不在同一个局域网，访问 `http://电脑IPv4:3000` 必然失败。可选方案：

| 方案 | 适合场景 | 做法 |
|---|---|---|
| 同一 Wi-Fi / 手机热点 | 最快本地真机调试 | 让电脑和手机连同一个网络，重新查电脑 IPv4 |
| 内网穿透 | 不在同一局域网也要临时真机测 | 用 cloudflared / ngrok 暴露本地 3000，得到 HTTPS 地址 |
| 公网 HTTPS 后端 | 稳定 UAT / 提审前 | 部署后端到服务器和备案域名，配置小程序合法域名 |

真机控制台可执行：

```js
getApp().debugApiHealth()
```

通过标准：

- 成功：弹窗显示 `API 连接成功`
- 失败：弹窗会显示当前 API 和微信底层错误，例如 `timeout` 或 `url not in domain list`

### 2.4.2 广东 110 小程序跳转

当前代码已经留好跳转能力，并已把你确认的“广东110”小程序 AppID 写入本地配置：

```text
wxf654be7f2931bfcb
```

注意：当前 `app.json` **不要**写 `navigateToMiniProgramAppIdList`。微信开发者工具新版会把该字段判为 invalid app.json；当前代码直接调用 `wx.navigateToMiniProgram`，自检已覆盖。

公开资料能确认“广东110”报警小程序存在，并且已嵌入微信等入口；公开网页没有可靠直接给出可复制 AppID，所以这个值仍建议你在微信“更多资料”里再肉眼核对一次。

获取 AppID 的可行方式：

1. 在微信里搜索并打开“广东110”官方小程序。
2. 点右上角“...”
3. 点小程序名称 / 头像进入“更多资料”
4. 复制 AppID。
5. 如需具体页面路径，需要使用目标小程序提供的页面路径，或按微信开发者工具的“获取更多页面路径”流程由可访问该小程序的微信号协助获取。

如果暂时无法拿到具体 path，v1 不阻塞上线：path 留空会尝试打开广东110小程序首页；跳转失败时仍使用当前兜底：

- 见面安全报备
- LBS 定位留存
- 紧急联系人
- SOS 证据记录
- 弹出“广东110打开失败”，展示微信底层 `errMsg`
- 引导用户在微信搜索“广东110”，并可复制小程序名称

配置方式：

在 `server/.env` 配置：

```env
GUANGDONG_110_ENABLED=true
GUANGDONG_110_APP_ID=wxf654be7f2931bfcb
GUANGDONG_110_PATH=
```

重启后端后，首页“安全求助”的 110 按钮和安全确认页 SOS 会直接尝试拉起广东110小程序，不再先弹“打开广东110 / 拨打110”的确认框。

实际点击路径：

1. 首页点粉色 `110`，或安全确认详情页点“一键呼救 110”
2. 小程序立即调用 `wx.navigateToMiniProgram`
3. 开发者工具只会显示“跳转成功”，不会真的打开另一个小程序
4. 真机才可能真实打开广东110

如果点 `110` 没有任何反馈，通常是手机仍在跑旧预览包；重新编译、重新扫码，并确认 Console 没有旧版本报错。

真机排查：

- 微信开发者工具模拟器不会真实打开另一个小程序，只会校验调用并显示“跳转成功”。
- 真机点击后才验证是否能真实拉起目标小程序。
- 若失败，页面会弹出“广东110打开失败”，显示微信底层 `errMsg`，并引导复制“广东110”去微信搜索。
- 失败常见原因：AppID 不对、目标小程序不允许被打开、当前不是用户点击触发、真机微信版本/调试环境限制。

合规口径：

- 现在做的是“方案一”：平台内见面安全报备 + 用户主动一键求助 + 跳转官方广东110小程序 + 平台留证。
- 不宣称“直连公安 110 接警系统”。
- 不把用户数据自动推送给公安。
- 其它社会小程序通常也是通过报备、定位、紧急联系人、拨号或跳转官方报警入口来做安全兜底；真正接入警情直推/公安背书属于后续方案二，需要警企合作、资质、等保、安全评估和官方接口授权。

- 19 个页面均能打开，无白屏
- 登录、注册、择偶配置、匹配查看、VIP、见面安全、客服、我的页菜单全部跑通
- 断网 / 未登录 / 空数据不崩
- 不出现用户隐私过度暴露：无头像、无私聊、无照片上传、无完整三观原文展示
- 见面安全功能文案温和，不像强制监管
- 发现的问题已按 P0/P1/P2 记录清楚
