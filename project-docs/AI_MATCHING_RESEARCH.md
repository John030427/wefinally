## 一、研究目标

为 WeFinally 严肃婚恋小程序设计可演进、可解释、合规的匹配体系：

- v1：**规则 + 权重**（现有 `matchService` 增强）
- v2（可选）：大模型生成匹配理由/破冰话题（默认关闭）
- v3（远期）：行为数据驱动的推荐系统

## 二、理论维度（待核实文献）

| 理论/构念 | 与婚恋匹配的关系 | 本项目可落地方式 |
|-----------|------------------|------------------|
| **相似性吸引** (Similarity-Attraction) | 价值观、态度相似提升好感 | 三观文本 Jaccard / 后期 embedding |
| **大五人格** (Big Five / OCEAN) | 开放性、尽责性等影响关系质量 | 轻量问卷或自报（D 组 MBTI 思路，v1 不做） |
| **依恋类型** (Attachment Theory) | 安全/焦虑/回避影响亲密关系 | 远期 5-8 题筛查 |
| **价值一致性** (Value Congruence) | 婚育、家庭、消费观一致 | 已有 `baby_plan` 最高权重 |
| **互补性 vs 相似性** | 部分维度互补（如性格）争议较大 | v1 以相似为主；圈层用白名单非真互补 |
| **临近性/熟悉性** | 同城更易见面 | 已有 `city` 权重 |
| **Gottman 婚姻研究** | 沟通模式、冲突处理 | 远期问卷维度 |

## 四、轻量心理/价值观测试设计（MVP 建议）

### v1 不新增独立心理测试

已有字段足够支撑路线 A：

- 婚育节奏 `baby_plan`（最高权重）
- 三观文本 `self_view_text` / `target_view_text`
- 年龄/身高/学历/圈层/城市

### 若 v2 增加轻量测试（15-20 题，待老板确认）

| 块 | 题量 | 用途 |
|----|------|------|
| 婚育与家庭 | 3-4 | 过滤 + 权重 |
| 生活方式 | 3-4 | 权重 |
| 冲突处理/沟通 | 2-3 | 权重 |
| 未来规划（城市/职业） | 2-3 | 权重 |
| MBTI 短版（可选） | 10-12 | **展示+话题**，权重 ≤20% |

**原则**（来自早期讨论，背景参考）：MBTI 作社交货币，不作唯一算法核心。

## 五、适合进入匹配算法的字段

| 字段 | v1 | 说明 |
|------|-----|------|
| baby_plan | ✅ 已实现 | 最高权重 |
| 三观文本 | ✅ 已实现 | Jaccard，权重第二 |
| age / height 区间 | ✅ | 硬性区间 + 部分分 |
| education | ✅ | 层级比较 |
| circle_id / like_circle_ids | ✅ | 白名单命中 |
| city | ✅ | 同城加分 |
| appearance_description | ⏳ 规划 | 默认不参与；`useAppearanceInMatch` 开关 |
| income / house_car | 可选 | 用户选填，权重低 |
| 行为数据（点击/见面确认） | v3 | 数据不足 |

## 六、心理学与合规注意

- 不向用户展示「科学保证」类承诺
- 匹配分为**辅助参考**，非决策唯一依据
- 三观原文不对外展示（已实现）
- 若引入 LLM：禁止上传可识别 PII；prompt 脱敏
- 中国个人信息保护法：匹配逻辑可解释、可申诉
