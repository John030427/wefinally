## 二、已确认需求（可直接开发）

### 2.1 PRD 核心（B 组，大部分已实现）

- 无照片/无私聊/无社交 UGC
- 微信登录 + 极简注册（全下拉）+ 三协议勾选
- 择偶六大维度 + 双三观文本（20-300 字）+ 7 天冷却
- 每周三/五 0:00 AI 空投匹配
- VIP 188 元/30 天，无自动续费
- 50/50 分润，T+7 结算
- 50 圈层合伙人风控
- 官方客服对接奔现
- 结婚报备/注销、离异后台审核、违规永封
- **被匹配对象不要求 VIP**（2026-06-29 确认）
- **双向互配**（2026-06-29 确认）

### 2.2 用户新增（C 组）

- **项目总目标**：提升女性安全感与线下见面转化
- **外貌描述**：`appearance_description` + `appearance_want`，选填；仅本人 + 后台可见，**不展示给对方**；以“自述 vs 期待”的偏好契合度计入匹配分，不做颜值评分（LLM 标签仍为增强项）
- **线下见面安全确认**：官方对接后的附加层；时间/地点/对象/说明/安全提示/状态/记录
- **见面安全方案一**：报备 + 前台主动 LBS 安全守护 + SOS 留痕 + 广东110跳转位；安全卡已撤下
- **配置化**：23 项参数统一配置（方案已确认），只读配置已由 `GET /api/common/config` 下发
- **AI 匹配 v1**：规则+权重为主；不接外部大模型

### 2.3 已确认的产品细节

| 项 | 结论 |
|----|------|
| 商业模式 | PRD：严肃婚恋 + 188/月 + 官方客服对接奔现（**John 已锁定，不采纳咖啡店 OMO**） |
| 离婚证明 | 图片或 PDF，后台人工审核（用户端无上传） |
| 安全确认定位 | 官方对接奔现**之后**的用户自我安全确认 |
| 算法 v1 | 三观 Jaccard + 关键词客服 — 够用 |
| 配置真源 | `server/src/config/*` + `GET /api/common/config` |
| **非 VIP 匹配详情** | 只看模糊提示 + 开通 VIP 引导；完整详情仅有效 VIP（Q1） |
| **匹配详情字段** | 收紧为最小集：年龄段/学历/职业圈层/婚育计划/基础硬性条件/身高区间/三观契合度；不展示姓名/照片/联系方式/性别/城市/精确身高（Q2） |
| **注册身高** | 立即改区间档位 + 旧精确数据兼容迁移（Q3） |
| **外貌描述** | 纯文本选填，仅本人+后台可见，**不展示给对方**；按外貌偏好契合度计入匹配分，不做颜值评分；LLM 标签仍为增强项 |
| **三观文本** | 选填，但**填了校验 20–300 字**（B-Q1） |
| **见面安全卡** | 已撤下；当前执行老板方案一：报备、定位守护、SOS、广东110跳转位；安全确认强引导不阻断（B-Q3） |
