## 2. 项目背景（产品与红线）

- 纯结婚导向的严肃婚恋微信小程序；**无头像、无用户间私聊、无社交动态**，官方客服协调线下见面（`open-type="contact"`）。
- 技术栈：原生微信小程序 + Node/Express + MySQL8（本地）+ CloudBase NoSQL（云端 api / agent-graph / report-worker / login 云函数）+ LangGraph（客服、双边约会协调，可暂停/恢复）。
- 50 圈层合伙人 50/50 分润；成功匹配一次占用 A/B 双方（原子约束）。
- 硬性红线（AGENTS.md / plan.md）：
  - LBS 必须用户主动授权，不后台静默采集；不宣称"直连 110"。
  - Agent/模型不扫描全库、不直接写库、不绕过确定性权限；不向模型发送手机号/OpenID/精确地址/密钥。
  - 不修改支付、分润、`matchCron` 节奏、`init.sql` 已上线结构（表变更只写 `database/patch-*.sql`）。
  - 发布动作（部署 api / 上传小程序 / 改生产数据）必须单独授权；CloudBase 只允许 MCP。
  - 用户既有 dirty 文件归用户所有，禁止 reset/clean/checkout/restore/覆盖。

1. **受控双用户约会协调 E2E（云端真实验收）**：已通过 `passed / arranged`，对应
   `server/selfcheck/controlled-date-langgraph-e2e.js`（在 `selfcheck:agent` 内）。
2. **QA 真人 → synthetic fixture 模拟约会**（plan.md §9，约会测试闭环）：
   - 入口：匹配详情「发起测试约会申请」（fixture 徽章，不伪装真人）；
   - 提交：`fixture-applications` → 幂等 `fixture_response_job`（延迟 = HMAC(interaction_id:fixture_run_id) → 2–6h）；
   - 到期：worker 写 `source_type=fixture_simulation` 婉拒事件，`notify_sms/subscribe/create_human_ticket=false`；
   - 无任何真实协调/通知/工单/arranged/支付/佣金副作用；
   - 自检：`fixture-response-job.js`、`match-only-fixture-safety.js`（在 `selfcheck:cloud-match` 内）。
