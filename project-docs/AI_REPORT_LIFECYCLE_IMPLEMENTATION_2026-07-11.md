# AI Report Lifecycle Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Make AI match reports asynchronous, idempotent, structured, privacy-scoped, retryable, and independent from match creation.

**Architecture:** Store one durable task per bidirectional match and report version in `ai_report_tasks`. The API only creates or reads tasks; a timer-triggered `report-worker` claims tasks, calls MiniMax for A and B in parallel with isolated inputs, validates both structured reports, and persists the result. Match detail reads the task as the only report-state source while retaining legacy fields only for migration.

**Tech Stack:** WeChat CloudBase, Node.js 16, wx-server-sdk, MiniMax Anthropic-compatible API, native selfcheck scripts.

## Global Constraints

- Only approved members with active VIP may match or view reports.
- A succeeded report cannot be regenerated by a user.
- One model call creates privacy-isolated A and B reports.
- Historical reports are generated lazily on open or explicit click.
- Successful report content expires after 12 months; input snapshots after 30 days.
- Account cancellation immediately blocks access and removes report data within 15 days.
- Do not expose MiniMax keys or add Redis, queues, Agent frameworks, or cloud hosting.
