# 真机重新注册与匹配结果测试资料

适用日期：2026-08-30。此方案只用于两台真实微信账号的受控 QA，不用于正式用户造数。

## 测试前置条件

两台真机账号都需要满足：

- `account_mode` 保持 `production`，并单独设置 `qa_test_run_enabled = true`；不要改成 `internal_qa`，后者按现有安全规则不进入正式候选池。
- 会员审核状态为 `approved`，VIP 在有效期内，账号状态为正常。
- 两台账号都从首页“内部 QA”区域点击“重新注册测试资料”。该动作会给两台账号写入同一个隔离测试组 `qa-real-device-registration-v1`，测试组只能匹配组内账号，不会匹配正式用户。
- 完成资料和择偶配置后，再运行下一轮匹配。如果两人历史上已经互相匹配过，必须让两台账号都在该历史匹配之后各完成一次新的重录；只重录一方仍会被历史去重拦截。

“重新注册测试资料”不会删除账号、历史匹配、订单、VIP、推广归属或审核状态；它只开启一次性资料重录、清空当前择偶配置并解除 7 天编辑冷却。每台手机成功提交重录资料时，服务端会生成新的 QA 匹配轮次；客户端不能自行指定该轮次。

## 注册页身份选择

1. “主要身份”仍通过原有板块/职业选择器完成。
2. “其他符合身份”不再一次平铺几十个标签。点击“选择其他身份”打开底部抽屉。
3. 可在抽屉搜索职业名称或板块名称，也可按板块浏览；主要身份不会再次出现在候选中。
4. 最多选择两个补充身份。达到上限后继续点击未选项会提示限制；点击已选区中的“移除”可以取消。
5. 点击“完成”或“关闭选择”返回注册表单，最终仍通过现有 `secondary_circle_ids` 保存。

可以继续使用同两台手机，分别点击“重新注册测试资料”后录入以下差异。其余字段沿用第一轮。两边都会在候选排序前被年龄硬条件过滤，因此不会互相匹配。

- 手机 B（女）：出生年份改为 `2001`；期待年龄改为 `20-25岁`。

验证依据：2026 年手机 A 约 48 岁，不满足手机 B 的 20-25 岁；手机 B 约 25 岁，不满足手机 A 的 45 岁以上。年龄会随时间继续增长，之后也不会重新落入对方区间。

## 匹配结果动画验证

1. 完成一次匹配后，不要先打开首页，在匹配日期之后再打开小程序。
2. 首页取得最新匹配后，会显示“新的匹配已经抵达”动画。
3. 点击“立即查看”进入该条匹配详情，并将该匹配永久标为本机已看。本地存储写入失败时仍应进入详情。
4. 点击“稍后再看”只在当前小程序会话内收起；同一会话不重复弹出。彻底关闭后下一次冷启动仍应再次显示，直到点击“立即查看”。
5. 已看记录按用户 ID 存在本机，不会串到另一台测试账号。

## 跨轮重复匹配验证

1. 先确认手机 A 与 B 已存在一条历史匹配。
2. 只让手机 A 完成一次“重新注册测试资料”，运行匹配：预期仍被历史去重拦截。
3. 再让手机 B 也完成一次重录，确保两边提交时间都晚于旧匹配，运行匹配：预期允许在新的 QA 轮次互配。
4. 不进行新重录再次运行同轮匹配：预期本轮新 claim 继续拦截重复交付。
5. 在后台核对历史记录仍存在；测试过程不应删除或改写旧 claim。
