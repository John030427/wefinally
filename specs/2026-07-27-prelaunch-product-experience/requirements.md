# 上线前产品体验优化需求

## 背景

WeFinally 已具备注册、会员审核、匹配、线下约会协调和安全能力，但首次使用的信任说明、资料完成度、首页下一步、匹配结果理解以及约会后反馈尚未形成连续闭环。

## 用户故事与验收标准

### R1 首次信任引导

- WHEN 用户首次打开小程序 THEN 系统 SHALL 展示“审核制、隐私边界、匹配节奏”三段信任说明。
- WHEN 用户完成或跳过引导 THEN 系统 SHALL 记录本机已读状态，并进入登录页或首页。
- WHEN 已读用户再次打开 THEN 系统 SHALL 不重复打断正常访问。

### R2 资料完成度

- WHEN 用户进入“我的”或首页 THEN 系统 SHALL 根据匹配所需字段计算资料完成度。
- IF 存在缺失字段 THEN 系统 SHALL 展示缺失项和明确的完善入口。
- IF 必填资料完整 THEN 系统 SHALL 展示可参与审核/匹配的就绪状态。

### R3 首页状态主线

- WHEN 用户进入首页 THEN 系统 SHALL 按“资料未完整、待审核、待开通、等待匹配、已有匹配”选择唯一主行动。
- WHEN 用户点击主行动 THEN 系统 SHALL 跳转到与当前状态相符的页面。
- IF 会员审核未通过 THEN 系统 SHALL 在首页解释当前状态，而不是无条件强制跳走。

### R4 匹配详情与结果反馈

- WHEN 用户打开匹配详情 THEN 系统 SHALL 首屏展示匹配理由、需要确认的差异和数据限制。
- WHEN 用户需要了解算法 THEN 系统 SHALL 允许展开原有评分及报告细节。
- WHEN 用户提交“准确、部分准确、不准确”反馈 THEN 系统 SHALL 通过白名单 API 幂等保存，且不得接受不属于当前用户的匹配记录。

### R5 约会后反馈

- WHEN 双方已完成日期协调且状态为 arranged THEN 系统 SHALL 提供约会后反馈入口。
- WHEN 用户提交是否见面、继续意愿、资料一致性和安全感受 THEN 系统 SHALL 通过白名单 API 幂等保存。
- IF 协调未安排或用户不是参与者 THEN 系统 SHALL 拒绝写入。
- WHEN 用户选择不安全或明显不一致 THEN 系统 SHALL 支持申请人工复核，但不把自由文本直接用于自动处罚。

## 非功能约束

- 不部署、不提交、不批量修改生产数据库。
- 小程序端不得直接写反馈集合。
- 反馈枚举、文本长度、匹配归属和协调状态必须由云端再次校验。
- 不保存手机号、OpenID、密钥、私钥或聊天全文。
- 既有匹配评分、AI 报告、会员与安全流程保持兼容。
