# AI 匹配报告 UI 优化设计

## 目标

将匹配详情页的 AI 报告从连续灰色长文本改为温柔粉色高级感的分层报告，提高移动端扫读性，同时保持现有品牌风格、接口数据和报告生成流程不变。

## 视觉方向

- 使用低饱和柔粉、白色和少量暖杏色，不增加重装饰或插画。
- 主卡保持现有圆角和阴影，内部通过浅色分区、标题、图标与留白建立层级。
- 正文使用深灰而非浅灰，提高对比度；辅助说明和报告局限降低视觉权重。
- 视觉重点依次为：报告状态与总分、核心摘要、契合点、需要磨合、行动建议、报告局限。

## 页面结构

### 1. 报告标题

- 左侧为小型 AI 标识、标题和一句轻量副标题。
- 右侧保留当前状态标签；成功、生成中和失败沿用现有状态语义。

### 2. 核心摘要

- 使用柔粉渐变摘要面板。
- 总分从 `aiReport.overall_score` 展示为醒目数字；无有效分数时不显示分数区域。
- 展示质量门槛标签，但不暴露内部字段名。
- 摘要正文单独成段，采用舒适行距。

### 3. 契合点

- 每项为独立白色小卡。
- 使用粉色勾选标识，标题和说明分成两行。
- 空数组时整个区块不渲染。

### 4. 需要磨合

- 使用低饱和暖杏色背景，与契合点区分但不制造警告感。
- 显示标题与说明，不直接展示 `severity:medium` 等模型内部枚举。
- 空数组时整个区块不渲染。

### 5. 行动建议

- “沟通建议”和“初次见面建议”分别成区。
- 每条使用 `01`、`02` 等序号，便于扫读和执行。
- 不修改模型返回文本。

### 6. 报告局限

- 放在底部灰粉提示框中，使用低强调图标和字号。
- 保留全部局限内容，不折叠、不隐藏。

## 数据与兼容

- 不修改后端接口、任务状态、轮询、重试或 MiniMax 生成逻辑。
- 在页面数据规范化阶段生成展示模型，包括安全数组、分数可见性和带序号的建议项。
- 对旧报告、缺失数组、缺失 `overall_score` 和纯文本临时报告保持兼容。
- 生成中、失败、禁用、过期和待生成状态继续使用现有操作逻辑，仅统一视觉样式。

## 验证

- 先补 UI 合约失败测试，覆盖新结构类名、分数条件渲染、建议序号和原始 severity 不展示。
- 运行 `selfcheck:ai-report`、`selfcheck:agent` 与相关小程序页面语法检查。
- 在微信开发者工具检查成功、生成中、失败以及字段为空四种状态的排版。

## 非目标

- 不修改 AI 报告文案和评分算法。
- 不新增图片资源、动画、分享海报或折叠交互。
- 不调整匹配详情页其他业务卡片。
