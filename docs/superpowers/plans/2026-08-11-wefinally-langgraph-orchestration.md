# WeFinally LangGraph Orchestration Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Build a production-shaped LangGraph state machine for WeFinally customer service and bilateral date coordination while preserving the current API as the only business-action executor.

**Architecture:** Add a Nodejs20.19 TypeScript Event Function named `agent-graph`. The graph owns routing, checkpointed workflow state, interrupts, and structured decisions; the existing `api` function owns user identity and every business read/write. `api` invokes the graph, validates any returned tool request against the existing allowlist, executes it, and resumes the graph with a sanitized result.

**Tech Stack:** TypeScript 5, Node.js 20.19, `@langchain/langgraph@1.4.9`, `@langchain/core@1.2.5`, `@langchain/langgraph-checkpoint@1.1.3`, Zod 4, CloudBase Event Functions, DeepSeek OpenAI-compatible API, Node test runner.

## Global Constraints

- The model must never receive phone numbers, OpenID, secrets, private keys, exact addresses, another user's raw messages, or unrestricted database records.
- The graph must not execute arbitrary model-selected code or database operations.
- All business mutations remain in allowlisted services inside the existing `api` function.
- Checkpoint storage contains only bounded graph state and expires according to retention policy; it does not duplicate full chat history.
- Internal `threadId` values are generated by WeFinally and never depend on a provider conversation identifier.
- Matching, AI match reports, membership, payment, and existing backoffice contracts remain unchanged.
- `LANGGRAPH_ENABLED=false` must preserve the current behavior; `LANGGRAPH_SHADOW_MODE=true` must not execute graph-requested tools.
- Every implementation task follows red-green-refactor and ends with a focused commit.
- No CloudBase deployment or Mini Program upload occurs during implementation; deployment requires a separate gate and explicit confirmation.
